# Skycoach Reels Analyzer

Веб-сервис: принимает до 20 ссылок на Instagram Reels, в фоне собирает метрики и определяет,
есть ли в ролике реклама Skycoach, насколько она заметна и есть ли замечания к размещению баннера.

**Развёрнутый сервис:** _ссылка появится после деплоя_
**Демо всех состояний без бэкенда:** `/?mock=1`

## Что выдаёт по каждому ролику

| Поле | Как получено |
|---|---|
| Просмотры, лайки, комментарии, дата, автор | Apify. Недоступное (скрытые лайки, удалённый ролик) — `—`, никогда не 0 |
| Класс интеграции 0 / 1 / 2 | правила + LLM по подписи, речи и тексту на экране |
| Заметность 1–5 | считается кодом из измеренных фактов |
| Обоснование | секунды баннера в кадре и интервалы, доля кадра, позиция, текст и промокод на баннере, цитаты из речи, призыв в подписи, расчёт балла |
| Размещение по правилам Skycoach | замечания и удержание: обрезан 20 %, мелкий 20–30 %, перекрыт интерфейсом 20 %, не виден — исключение |

Пример обоснования:

```
4/5 · Реклама · баннер 9 с (85%), ≈7.1 % кадра · без замечаний
Баннер: в кадре ≈9 с из 11 (85%), 0:02–0:11; вверху по центру (≈8.5–19 % высоты);
ширина ≈68 % кадра, площадь ≈7.1 %. Текст: «SKYCOACH ELITE BOOSTING, WINS & LEVELING CODE: VALFUN».
Промокод: VALFUN.
Голос: речи нет.
Подпись: Skycoach не упоминается.
Заметность 4/5: размер ≈7.1 % кадра → 3; +1: в кадре 85% ролика.
Размещение по правилам Skycoach: без замечаний.
```

## Как запустить локально

Нужен Python 3.12. ffmpeg ставить не обязательно — для локального запуска он приходит
из пакета `imageio-ffmpeg`.

```bash
pip install -r requirements-dev.txt
cp .env.example .env        # вписать APIFY_TOKEN, AI_API_KEY, AI_BASE_URL
uvicorn app.main:app --reload      # веб: http://localhost:8000
python -m app.worker               # воркер, во втором терминале
pytest                             # 34 теста
```

Или в Docker (web и воркер — отдельные сервисы, общий volume с базой):

```bash
docker compose up --build
```

## Архитектура

```
Браузер ──► FastAPI ──► SQLite (WAL) ◄── Воркер
            POST /api/jobs   reels, jobs      │
            GET  /api/jobs                    ├─► Apify: метрики + ссылки на видео и звук
            GET  /  (UI)                      ├─► ffmpeg: кадры 1/с, аудио
                                              ├─► Whisper (NeuroAPI): речь с таймкодами  ┐ параллельно
                                              ├─► Gemini (NeuroAPI): баннер на кадрах   ┘
                                              └─► GPT (NeuroAPI): класс по речи/подписи
```

- **API сразу возвращает ID задач**, результаты появляются по мере готовности; страница опрашивает
  `GET /api/jobs?ids=…` каждые 3 с, ID хранятся в браузере — таблица переживает перезагрузку.
- **Очередь — в той же SQLite.** Воркер атомарно забирает пачку `UPDATE … RETURNING`, все ссылки
  пачки уходят в Apify одним запуском, анализ — до 3 роликов одновременно. Для 20 ссылок за раз
  отдельный брокер (Redis) не нужен; когда понадобится — см. «Что дальше».
- **Повторная ссылка не обрабатывается заново.** Ролик хранится один раз по shortcode
  (`/reel/X`, `/reels/X`, `/p/X`, `?igsh=…`, `instagram.com/автор/reel/X` — один и тот же ролик),
  уникальный индекс + `INSERT … ON CONFLICT` защищают от гонки. Повтор отдаёт готовый результат
  с пометкой «из кэша».
- **Надёжность.** Ошибка одного ролика не трогает остальные; сбои внешних сервисов —
  до 3 попыток, потом статус «Ошибка» с текстом; зависшие после перезапуска задачи
  возвращаются в очередь; метрики сохраняются ещё до анализа.

Код: `app/main.py` (API), `app/jobs.py` (приём и дедупликация), `app/worker.py` (очередь),
`app/scraper/apify_reels.py`, `app/pipeline/` (анализ), `app/static/` (интерфейс).

## Внешние сервисы и почему

| Сервис | Зачем | Почему он | Стоимость |
|---|---|---|---|
| **Apify** `apify/instagram-reel-scraper` | метрики, ссылки на видео и звук | С IP облачного сервера Instagram почти всегда требует логин; yt-dlp/instaloader потребовали бы аккаунт и cookies (баны, нестабильность). Официальный актёр Apify это решает | ≈$0.0026 за ролик |
| **NeuroAPI** — OpenAI-совместимый шлюз | доступ ко всем моделям одним ключом | один счёт, оплата из РФ; модель меняется в `.env` без правки кода | по тарифу шлюза |
| — **gemini-3.8-flash** | баннер на кадрах: рамка, текст, промокод | сравнил 4 модели на одних кадрах: точнее всех по рамкам, без ложных срабатываний; claude-haiku пропустил мелкий баннер, gpt-4o-mini через шлюз считает картинку как текст (дорого) | ≈1.1 тыс. токенов на кадр, ≤60 кадров |
| — **whisper-1** | речь с таймкодами | таймкоды по фразам нужны для цитат в обосновании | за минуту аудио |
| — **gpt-5.4-mini** | класс 1/2 по речи и подписи | дешёвая текстовая модель, вызывается только если Skycoach где-то найден | копейки |

Модели и все лимиты настраиваются через `.env` (см. `.env.example`).

## Как считаются класс и заметность

**Класс.** Skycoach нет нигде (кадры, подпись, речь, текст на экране; регулярка ловит
«sky coach», «скайкоуч») → **0** без вызова LLM. Промокод на баннере → **2**. Иначе LLM решает
1 или 2 по речи и подписи. Признаки «упоминание/призыв в подписи» проверяются по тексту, а не
берутся у модели (на прогоне она путала текст баннера с подписью).

**Заметность 1–5** — кодом, не LLM:

| | |
|---|---|
| размер баннера, % площади кадра | < 4 → 1, < 6 → 2, < 9 → 3, < 13 → 4, иначе 5 |
| время в кадре | < 10 % ролика → −1, ≥ 50 % → +1 |
| голосовой призыв или призыв в подписи | +1 |
| баннера нет | 2 при призыве, иначе 1; класс 0 → «—» |

**Размещение** — по правилам из примеров выплат Skycoach: площадь < 4 % → «слишком маленький»
(30 %), < 6 % → «немного мелкий» (20 %); баннер касается одного края кадра → «обрезан» (20 %);
заходит в зоны интерфейса Reels (шапка, строка подписи и музыки, кнопки справа) → «перекрыт» (20 %);
не найден → исключение. Несколько замечаний — наибольшее удержание.

## Проверка на примерах Skycoach

Прогнал все 40 ссылок из примеров выплат (`banner_review_examples.docx`):

- 13 ссылок — YouTube / TikTok / Facebook → «Неверная ссылка» (сервис по заданию — для Instagram);
- 7 роликов удалены, 1 с возрастным ограничением → «Недоступен» с причиной;
- **19 живых роликов: удержание совпало с решением Skycoach в 19 из 19**
  (17 «без замечаний», «слишком маленький» −30 %, «маленький и перекрыт» −20 %).

Честная оговорка: два порога (площадь и нижняя зона интерфейса) подбирались на этих же роликах,
так что это проверка калибровки, а не независимая оценка точности.

## Кейсы приёмки

| Кейс | Поведение | Проверено |
|---|---|---|
| Невалидная ссылка | сразу «Неверная ссылка», без внешних вызовов | вживую |
| Удалённый ролик | «Недоступен: … Post does not exist» | вживую (7 шт.) |
| Приватный / с ограничением | «Недоступен» с причиной от Instagram | вживую — возрастное ограничение; приватного под рукой не было |
| Одна ссылка дважды (в т. ч. в другом формате) | готовый результат, «из кэша», без нового запуска Apify | вживую |
| Ролик без звука | «Звука нет — анализ только по изображению и подписи»; отличаем отсутствие дорожки, беззвучную дорожку и звук отдельным потоком | синтетика + 3 реальных ролика со звуком отдельно |
| Длинный ролик | равномерная выборка 60 кадров, речь — первые 15 минут, пометка в обосновании | синтетика 10 мин |
| Фото / карусель по `/p/` | метрики + «Недоступен: публикация не содержит видео» | тест |
| Больше 20 ссылок, пустой запрос | понятная ошибка 422 | тест |

## Ограничения

- **Зависимость от Apify и Instagram.** Если Instagram поменяет выдачу, данные пропадут до
  обновления актёра. Тексты ошибок от Instagram (`Post does not exist`) показываются как есть.
- **Просмотры = `videoPlayCount`** — то, что Instagram показывает у Reels. Метрики — снимок
  на момент первой проверки и сами не обновляются.
- **Доля кадра — оценка модели по рамке** (±1 п. п.), секунды — с точностью до шага между
  кадрами (1 с; у длинных роликов — шаг выборки, короткий показ может между кадрами проскочить).
- **Зоны интерфейса Instagram заданы для 9:16.** Правила «обрезан» и «перекрыт» проверены
  синтетикой и тестами — живых таких примеров среди Instagram-роликов не нашлось.
- **Скорость:** 30–150 с на ролик, больше всего — транскрипция у шлюза и повторы при его
  перегрузке. Пачка из 20 роликов — около 10–15 минут.
- **SQLite и один инстанс.** Web и воркер в одном контейнере с общим volume; горизонтально
  не масштабируется.
- **Публичный URL без авторизации**, поэтому есть защита расходов: 20 ссылок на запрос,
  20 отправок с IP за 10 минут, 300 новых роликов в сутки (уже проверенные — без лимита).

## Что бы сделал дальше

1. **Обновление метрик по расписанию** — для выплат важны просмотры на дату выплаты, а не на дату первой проверки.
2. **Поддержка YouTube Shorts и TikTok** — треть ссылок в примерах Skycoach с этих площадок; пайплайн анализа от площадки не зависит, нужен только скрапер.
3. **Детектор логотипа (YOLO) по разметке** вместо LLM на кадрах — точнее и в разы дешевле на потоке; калибровка порогов на большей выборке, включая реальные «обрезан» и «перекрыт».
4. **PostgreSQL + Redis/RQ и несколько воркеров**, Alembic для миграций — когда поток вырастет.
5. **Перевод ошибок Instagram** на понятный менеджеру язык, авторизация, выгрузка в Google Sheets.
